# 盤面の位置関係（将棋 9×9 マス／囲碁 19 路交点）

「どのマス・交点がロボット座標のどこか」を 1 か所に整理したメモです。
**将棋の数式の正本は `shogi/app/board_map.py` です。** ここは読み解きと、囲碁へ広げるときの設計置き場です。
実寸は未実測のものが多いので、断定せず「仮定／実測済み」を分けて書きます。

## 共通の考え方

- ロボットと人は盤の**長辺側**で向かい合う（将棋の現行想定）。
- 盤の中心をロボット座標の基準点に置き、盤の平行移動（x, y）と回転（yaw）だけを
  パラメータ化する。マーカーで測る盤四隅 → 盤座標 → ロボット座標、の順に変換する。
- 画像上の四隅補正（真上から見た画像にする処理）と、ロボット座標への較正は別物。
  前者ができても後者ができたことにはならない（将棋側 README の注意を参照）。

## 将棋盤（実装あり：`shogi/app/board_map.py`）

### 仮定寸法（コード内定数、実盤の実測ではない）

| 量 | 値 | 出典 |
| --- | --- | --- |
| 盤中心のロボット座標 | X = 0.19 m, Y = 0 | `BOARD_X`, `BOARD_Y` |
| 盤の外形（筋方向 × 段方向） | 330 mm × 360 mm | `BOARD_W`, `BOARD_L` のコメント |
| マス間隔（筋） | 330 / 9 ≒ 36.7 mm | 上記から導出 |
| マス間隔（段） | 360 / 9 = 40.0 mm | 上記から導出 |
| 盤ずれの許容範囲（入力チェック） | X 0.15–0.40 m、Y ±0.12 m、yaw ±25° | `set_pose()` |

### マス中心の式（USI 表記 `file` = 1–9、`rank` = a–i）

```
dx = direction * ((9 - file) - 4) * (330mm / 9)
dy = direction * (4 - rank_index) * (360mm / 9)   # rank_index: a=0 … i=8
(x, y) = 盤中心 + R(yaw) · (dx, dy)
```

- `direction` は AI 側が先手なら +1、後手なら −1（盤を 180° 回した扱い）。
- 駒の向き: 自駒は段方向。先手（black）−90°、後手（white）+90°（`piece_yaw_deg()`）。
- 並びのイメージ（ロボットから見て）: X が筋方向（人方向）、Y が段方向。
  設計計画では「現行 `board_map.py` は筋方向がロボット→人で通常の対局配置と異なる」
  と指摘済み。座標定義の統一は未完了の課題（Issue 参照）。

### 駒台（仮置き、未確定）

- 現行は「手前段の横の単一仮スロット」: `(盤中心X − 0.04 m, 盤中心Y − 0.20 m)`（`stand_xy()`）。
- これは対局を完走できる駒台ではない。駒種ごとのスロット化、全スロット到達確認、
  取った成駒を表に戻す処理が課題。設計方針は `shogi/docs/shogi-implementation-plan.md`。

### マーカー配置

- ArUco 4 枚（ID 0,1,2,3）を 9一、1一、1九、9九 の外側に置き、黒い角を格子の角に合わせる。
  印刷は `shogi/app/board_markers.svg` を A4・100%、黒正方形の一辺 26 mm。
- 盤と一緒に動くよう固定する。駒台・裏返し台は盤と一緒に動くとは限らないので個別に測る。

## 囲碁盤（未着手：設計メモのみ）

実装はまだ無い。始める場合は将棋の「四隅→盤座標→ロボット座標」の枠組みを流用し、
次を実測してからコード化する。

| 項目 | 将棋との違い | 決めること |
| --- | --- | --- |
| 目印の単位 | マス中心ではなく**交点** | 19 路なら交点間隔（一般に約 22 mm、実盤を実測） |
| 座標の数え方 | 筋×段 = 19×19 交点 | 左下／右上どちらを原点にするか、ロボットから見た向き |
| 石の扱い | 平たい駒ではなく円盤状の石をつまむ／置く | グリッパー開度、石径・厚さ、隣接石との干渉 |
| 置き場 | 駒台ではなく石の容器（碁笥） | 碁笥位置、石の取り出し方、取った石の置き場 |
| ルール | 着手・コウ・アゲハマ | 採用するルールエンジンと局面管理（未選定） |
| 盤サイズ | 19 路が届かない可能性が高い | 9 路／13 路から始めるか、盤位置と延長寸法を先に評価する |

到達範囲の評価方法（全交点の IK・接触検査）は将棋の `shogi/simulation/` の枠組みを
19×19 交点に差し替えて流用できる見込みだが、未実施。

## 実測したら更新すること

1. 実盤の外形・厚さ、マス／交点間隔を測り、この表の「仮定」を「実測（日付）」に替える。
2. 駒（将棋駒・碁石）の幅・長さ・厚さと、爪先寸法を測る。
3. 盤中心 X/Y・yaw の再現性（観測姿勢に戻すたびのばらつき）を記録する。
4. 数式を変えたら `shogi/app/board_map.py` とテスト（`shogi/tests/test_board_tracking.py` 等）を一緒に直す。
