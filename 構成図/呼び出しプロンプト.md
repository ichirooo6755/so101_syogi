# 構成図の呼び出しプロンプト

次の文で呼び出せます。

> so101_syogi の構成図を表示せよ。構成図/呼び出しプロンプト.md に従い、正本JSONの最新進捗で色を生成せよ。

## 対象の構成

- 共通の観測・較正から **将棋／囲碁／チェスの3分岐** を表示し、共通搬送・実機制御・再確認へ合流する。
- 将棋AIは **やねうら王（YaneuraOu）／USI**、チェスAIは **Stockfish／UCI**。囲碁AIは未選定。
- チェスの分岐には8×8認識・盤座標・局面管理・AI・回収先と交換駒・操作計画を含める。
- エンジンの採用と実装・検証を区別し、実際の進捗と色は必ず正本JSONから読む。

## 表示手順

1. 対象は `ichirooo6755/so101_syogi`。ローカルの対象チェックアウト、または接続済みGitHubの現在のmainを参照する。ユーザーがブランチを指定した場合はそれを優先し、正本と図設定を同じコミットから読む。
2. `構成図/構成図.json` と `構成図/図設定.json` を読む。過去の会話や保存済みMermaidを進捗の正本にしない。
3. ローカルで実行できる場合は `python 構成図/show.py show` を実行し、その出力をMermaidとして表示する。Macではpython3、Windowsではpy -3でもよい。
4. GitHub参照だけの場合は、同じJSONから生成する。表示対象は図設定のlabels、列はgroupsの全グループ（将棋・囲碁・チェス）を省略せず使い、接続はtarget_architecture.edgesのdiagramがfalseでないものを使う。方向はTB。
5. 各ノードの色はmodules[].statusをstatus_definitions[].styleへ対応させて生成する。fill・stroke・stroke_width・dashを使い、見た目から進捗を推測しない。
6. 既存実装・試作未統合・予定・実装中・ソフトウェア検証済み・実機検証済み・課題停止を区別する。凡例と更新日を短く添える。
7. 表示だけの依頼では進捗やファイルを変更しない。構成図を表示して完了し、追加の確認待ちにしない。

## 実装の進捗更新も依頼された場合

- 対象の変更内容と試験結果を確認し、構成要素IDと状態を選ぶ。コードの存在だけで検証済みにしない。
- `python 構成図/show.py set-status <module_id> <status> --evidence "確認したコミット・条件・結果"` で根拠つきの履歴を記録する。
- その後 `python 構成図/show.py check` を実行し、正本・互換JSON・構成図・計画内の図が一致することを確認する。
- 実行できない環境で編集する場合も、正本を先に更新し、生成器と同じ規則で生成物を揃える。実行していないチェックを実行済みと記載しない。
- 実機の送信ゲートは進捗表示と別の制御であり、状態更新のために解除しない。
