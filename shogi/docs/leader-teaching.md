# 届きにくいマスの教示

2026-11-06 の[開発計画](shogi-implementation-plan.md)では、延長 Follower と公式 LeRobot を使う方針に変更しました。以下は現行の標準腕用機能の説明です。延長後の連続教示・学習・再生は未実装で、既存の記録をそのまま延長腕へ適用しません。

## 今できること

アームは標準の長さのままにします。既存の計画や学習を試し、失敗したマスだけを追加で教える方針です。学習モデルはまだシミュレーション用で、GUI の実機経路には入っていません。将棋 GUI は計画やシミュレーションの失敗から、原因の候補を「このマスでつかむ」「このマスに置く」に分けて表示します。運搬中や駒台の失敗など、マスを特定できない場合は候補を出しません。候補はあくまで原因の推定で、実機の到達可否を証明しません。

既存の学習済みモデルについて、仮の盤中心 X＝190 mm、後手、想定した隣の駒を置く条件で 9三・3六・3三の 3 例を試したところ、3 例ともモデル上で接触がありました。[試行結果](../output/stock_arm/learned_failure_samples.json)。GUI は、学習モデル、シミュレーションのコードとモデル、仮の盤配置・手番が試行時と一致するときだけ、この結果を教示候補に表示します。3 例だけで、実機や他の局面での失敗率を示すものではありません。

学習済みモデル `simulation/runs/waypoint_id5/policy.pt` とシミュレーション用の依存先 `vendor/` は GitHub に含めていません。新しい環境では [シミュレーションの手順](../simulation/README.md)に沿って準備・学習し、現在の盤条件で再試行してください。たとえば盤中心 X＝190 mm・後手なら、次のコマンドで GUI が読む場所に結果を保存します。現在の試行結果ファイルは上書きされます。

```sh
.venv-sim/bin/python simulation/scan_stock_learned.py --center-x 0.19 --side white --out output/stock_arm/learned_failure_samples.json
```


「失敗したマスを Leader で教える」から候補を選ぶと、つかみ方は「上から近づく」「爪を合わせる」「つかむ」「持ち上げる」、置き方は「駒を持って近づく」「下ろす」「離す」「爪を離す」の 4 姿勢を記録できます。各姿勢で Leader と Follower の関節位置を両方記録し、失敗候補から始めた場合は、該当する指し手と失敗理由も記録に残します。

自動検知を停止し、盤とアームを固定したうえで両方の USB を選びます。各姿勢では腕を静止させ、USB を使用中の操作ソフトを切断してから記録してください。読み取りは既存の `syodo` Follower アダプターを使い、6 モーターの較正と動作モード、USB の重複使用、静止を確認します。Leader と Follower は同時ではなく短時間に順番に読み取り、サンプルに所要時間を残します。モーターの目標位置やトルク、較正値を書き換えません。保存先は `~/.cache/so101-shogi/teaching/` です。教示データを GitHub には自動送信しません。

**現状、将棋 GUI から Leader で Follower を追従させる機能はありません。** 書道側には姿勢合わせと追従の処理がありますが、盤や駒、グリッパーの条件での検証はまだです。4 姿勢の間の連続経路も記録しておらず、保存した姿勢は計画・学習・実機再生にまだ使いません。盤の位置は実測・保証されていません。Leader が後で接続されたら、両腕と較正を識別し、関節の向き・ゼロ点とグリッパー、追従中の停止を確認してから、連続記録と将棋用の経路検証につなぎます。

教示は、探索で見つからなかった実際の姿勢を得るのに役立ちます。ただし、腕の長さや関節範囲を超えて物理的に届かないマスを、姿勢の記録だけで届くようにはできません。盤が動いた後に、記録した関節角をそのまま使うこともできません。

既存の [LeRobot の SO-101 手順](https://huggingface.co/docs/lerobot/main/en/so101)は Leader / Follower の較正と遠隔操作の参考です。書道用の `syodo/scripts/hardware_write.py` の追従処理は、書道用の設定や安全範囲を前提にしているため、将棋 GUI からそのまま起動しません。
