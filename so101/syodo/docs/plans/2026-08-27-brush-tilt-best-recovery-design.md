# 筆傾斜アタッチメント込みで過去最高を超える回復設計

## 目的と成功条件

筆傾斜アタッチメント、38 mm 穂、固定 A4 の6書字枠を含む実機相当条件で、
過去最高モデル `kaisho-yohitsu-brushmark-joyo` を超える。

最終採択には全条件を必須とする。

- 常用漢字2,136字×6配置、計12,816ケースを評価する。
- 平均 beauty は **86.27775324466442 より高い**。
- p10 beauty は **83.78582694425683 以上**。
- 完筆率100%、Cゲート全項目通過。
- 滴下0、予定外接触0。
- 評価行数、文字数、配置数を検証し、欠損や重複を許さない。

過去最高値は単一配置の全2,136字評価で得た値である。そのため、最終評価は
より厳しい6配置を正本とし、旧モデルと同じ単一配置の補助評価も併記して比較条件の
違いを明示する。

## 現状

- 採択済み `sansetsu` は全2,136字で beauty 84.9608、完筆100%、Cゲート全通過。
- 過去最高 `brushmark-joyo` は beauty 86.277753、p10 83.785827。
- 動的傾斜 expert は代表10字×6配置を60/60完筆するが、beauty 72.96、
  消失布白41で、圧・幅・端点ゲートが未達。
- 固定45°スクリーンは `一三十`×6配置を18/18完筆、衝突0、消失布白0、
  端点は直立比+10.49で合格した。一方、beautyは約69.8で圧・幅が未達。
- layout 0 は物理45°で arm-floor 接触するため、安全な物理30°を使う。
- 単一の圧力gain、limit、scaleを変える試行では6配置を同時に合わせられなかった。

したがって、角度掃引や不良expertによるPPOを続けず、端点改善を保ったまま
圧力と幅の物理天井を先に上げる。

## 採用方式

### 1. 固定角と動的角度のハイブリッド

- 3画以下の単純字にある露出横画だけ、接地中の傾斜サーボを固定する。
- layout 0 は物理30°、その他は物理45°とする。
- 複雑字、接合画、縦画、払い、はねは既存の動的低角度制御を維持する。
- 接地前に姿勢を作り、接地後は筆先XYZを主タスクにする。
- 方策I/Oは6次元のままにする。固定角接地中は第6出力を無視し、XYZが
  160周期以上停滞した場合だけ既存の位置回復用自由度として解放する。

### 2. 姿勢・配置・運筆相を使う圧力逆モデル

単一の積分gainに全条件の定常偏差を吸収させず、接触前から基準Zオフセットを
与える小さなフィードフォワード逆モデルを追加する。

入力:

- layout class: 85 mm / 110 mm
- 実際の筆角度: 主に30° / 45°
- 運筆相: entry / send / corner / finish
- 目標圧

出力:

- 目標圧を得るための基準Zオフセット

モデルはニューラルネットワークではなく、較正データから作る単調な区分線形
テーブルとする。外挿はせず端点でclipする。圧力が増えるほど押し込みが減るような
非物理的ノットは、pool-adjacent-violatorsで単調化する。

既存のleaky integral制御は削除せず、フィードフォワード後の残差だけを小さく
補正する。接触喪失中は積分せず、再接地時はsoft-startする。旧方式は明示的な
機能フラグで完全再現できるようにする。

### 3. 圧力―幅変換の単一正本

`tip_width_from_pressure()` と `tip_pressure_from_width()` を正本とする。
計画幅、目標圧、実墨deposit、評価が同じ圧力―幅曲線を使う。逆モデルは必要Zだけを
出力し、幅を評価側で補正しない。これにより、圧ゲートと幅ゲートの矛盾や、評価値だけを
改善する補正を防ぐ。

## 較正データフロー

1. `一三十`×6配置の固定角スクリーンを実行する。
2. layout、文字、画、phase、角度、目標圧、実圧、Zオフセット、実幅、目標幅、
   opening、XY/Z誤差、接触力、dwell、衝突、hard-limitを記録する。
3. 過渡状態、失接触、衝突、XY誤差過大のサンプルを除外する。
4. layout class×角度×phase×目標圧ノットごとに必要Zの中央値を集約する。
5. ノットを単調化し、leave-one-character/layout検証で汎化を確認する。
6. calibration JSONへschema version、CAD寸法、brush設定、git SHA、生成CLIを保存する。
7. ゲート通過候補だけを設定へ明示的に採択する。CLIがソース既定値を自動変更しては
   ならない。

### Gate 0: 単体・回帰

- 逆モデルの補間、clip、単調性、schema、シリアライズ往復を検証する。
- 圧力→幅→圧の可逆性とplanner/deposit/evaluatorの一貫性を検証する。
- 固定角、第6出力無効化、停滞時回復、anti-windupを検証する。

- 各ケースの圧誤差中央値0.08以下、p90 0.18以下。
- 各ケースの幅比0.90以上1.10以下。

### Gate 2: 60ケース

`一三十目書飛鬱誠砕案`×6配置で次を満たす。

### Gate 3: 768ケース

- `brushmark-joyo` と同じ代表集合でも補助比較し、指標ドリフトを検出する。

### Gate 4: CUDA学習と全数評価

- 親は `runs/kaisho-yohitsu-brushmark-joyo/08-joyo/model.zip`。
- stage 8から広く再適応し、6次元I/Oを維持する。
- r1後に12,816ケースを8 shardで評価する。
- 未完筆、beauty 86.277753未満、C未達、p10側の例をhard-miningする。
- r2、r3は学習率を下げ、候補を次の辞書順で非退行選定する。
  1. Cゲート通過数
  2. 完筆率
  3. 平均beauty
  4. p10 beauty
  5. line_width + brushwork
  6. 端点形状
  7. harai
- 2ラウンド連続で改善しなければ停止し、未達を明記する。成功条件は下げない。

## エラー処理と安全策

- calibration JSONが未指定、欠損、schema不一致なら起動時に停止する。明示的な旧モード
  のみ従来制御へ戻せる。
- 未観測のlayout、角度、phaseは最近傍へ黙って流さず、安全fallbackとして動的低角度と
  従来Z制御を使い、件数を結果へ記録する。
- 圧力範囲外はclipし、clip率が閾値を超えた候補をGate 1で不採択にする。
- NaN/Inf、非単調ノット、Z可動域超過、異なるCAD/brush較正IDの混用を拒否する。
- 接触喪失中は積分せず、過圧かつリフト上限では既存の膠着回避を維持する。
- CUDA、Windows SSH、親ZIPが利用不能ならCPUへfallbackせず「未実施」として停止する。
- 既存run、canonical model、採択済みbest、ユーザーのdirty fileを上書きしない。
