# A4固定・38 mm筆の穂先運用によるCUDA回復学習

## Summary

- 60 mm書字枠は廃止する。A4縦置きを完全固定し、2×2では85 mm角、縦2文字では110 mm角で書く。
- 実機初期配置は紙中心 `(x=200 mm, y=0)`、台座高さ100 mmとする。多始点IK確認では、両サイズの外周・25°傾斜が位置誤差3 mm、姿勢誤差5°、関節余裕5°以内で衝突なく到達可能。
- 38 mm穂とオフセット付き傾斜アタッチメントは維持する。穂全体を押し潰す現在の圧力・線幅モデルをやめ、先端側だけを使う低圧モデルへ変更する。
- 最低合格は全評価平均beauty 85以上・完筆100%。過去の全2,136字最高値86.277を回復目標とし、85到達だけでは直ちに学習を止めない。
- 現在の60 mm physical候補、dirty worktree、既存run、採択済みモデルは上書きしない。

## Implementation Changes

- `PaperConfig`の物理A4寸法と文字枠を分離し、`WritingLayoutConfig`を追加する。2×2の中心は `(155/245 mm, ±66.75 mm)`、85 mm角、2文字は `(200 mm, ±66.75 mm)`、110 mm角とする。旧結果の再現用に60 mm設定も明示的に残す。
- 紙・台座位置をMJCFの固定値だけにせず設定から反映する。リセットIKは単一elbow-upシードから、NumPy/MuJoCoだけを使う決定的な多始点DLSへ変更し、位置・姿勢・衝突・関節余裕で解を選ぶ。
- 墨幅の`width_limit`による人工的な切り詰めを削除する。計画幅と実墨で同じ可逆な穂先曲線を使用する。

  - 圧力 `0/.10/.20/.30/.45/1.0`
  - 幅 `1.8/2.5/4.0/6.2/9.0/13.0 mm`
  - 新しい書字モードでは圧力を0.45以下、openingを概ね1.12以下に保ち、9 mm超の全開領域へ入れない。

- 筆圧プロファイルは現行値の0.52倍を初期値とし、送筆約0.20、起筆・止め約0.35～0.40へ下げる。`contact_pressure_gain=0.014`、`limit=0.0035`から開始し、未達時だけgain `{0.010,0.014,0.018}` × limit `{0.0025,0.0035,0.0045}`を評価する。
- 傾斜サーボを運筆中も動かす。

  | 運筆相 | 初期角度 |
  |---|---:|
  | 搬送・離筆 | 0° |
  | 露出した横画の起筆 | 30°から始め、最初の5%で送筆角へ戻す |
  | 横・縦の送筆 | 8° |
  | 払い・捺の送筆 | 12° |
  | 転折 | 20° |
  | 止め・回鋒 | 22° |
  | はね・払いの抜き | 4°へ連続的に起こす |

- 起筆角は `{25°,30°,35°}`だけをA/Bし、完筆、予定外接触、端点形状、beautyの順で選ぶ。45°を長時間維持する現行挙動は採用しない。
- PPOの6次元I/Oは変えない。旧モデル互換のためBCで第6出力をゼロへ戻した後、接地中だけ分析制御値に対する±8°の傾斜残差を許可する。搬送中は分析制御へ固定する。
- `stroke_minimum_gap=1.5 mm`とclearance機構は維持し、85 mm枠に合わせて`stroke_junction_tolerance=7 mm`へ戻す。強制滞留解消や一律の墨跡縮小は追加しない。

## Calibration and CUDA Training

- `diagnose_stroke_merge.py`へ実圧／目標圧、実幅／目標幅、実角度／目標角度、opening、接地サンプル数、消失布白、端点形状を記録する。
- `一三十目書飛鬱誠砕案`を全6配置でexpert評価する。完筆100%、衝突・hard limitゼロ、圧誤差中央値≤0.08・p90≤0.18、幅比0.90～1.10、opening p90≤1.12、消失布白≤14、鬱≤12,000サンプルをCUDA開始条件とする。
- 動的傾斜は直立アブレーションより端点形状を10点以上改善し、`一・十`の両端を尖らせる一方、`三`の横画分離、`十`の交差、`目`の接合を維持する。128字と実際の2文字／2×2用紙をコンタクトシートで確認する。
- 親モデルは過去最高の `kaisho-yohitsu-brushmark-joyo/08-joyo/model.zip`を使う。現行physicalモデルは使わない。
- Windows新規run `kaisho-yohitsu-brush-tilt-a4-tip-r1`は広い再適応としてstage 8から開始する。

  - PPO 2.5M、BC 180k×5
  - `SubprocVecEnv(spawn)`、`n_envs=8`、`bc_workers=8`
  - `n_steps=2048`、`batch_size=1024`、`learning_rate=1e-4`
  - `--device cuda`。CUDA不可時はCPUへフォールバックせず停止
  - 4個の85 mm枠と2個の110 mm枠を同じ割合で学習対象にする

- r1後は全2,136字×6配置をCPU 8シャードで評価する。未完筆、beauty 85未満、Cゲート未達の文字をhard-miningし、r2を`7.5e-5`、r3を`5e-5`で実行する。
- beauty 85を超えても86.277未満なら次ラウンドを続ける。2ラウンド連続で「Cゲート通過数、完筆率、平均beauty、p10、line_width＋brushwork、端点形状、払い」の順位が改善しなければ停止し、最高候補を保持する。

## Verification and Assumptions

- 単体検査は枠中心・寸法、圧力幅曲線と逆変換、動的角度、傾斜残差制限、多始点IK、旧モデルのI/O互換を対象にする。
- 最終成果物はモデルZIP、SHA-256、12,816評価行のCSV、`summary.json`、シャード完了数、CUDAログ、旧60 mm／新85・110 mm比較画像、2文字／2×2コンタクトシートを保存する。
- 最終合格は全配置完筆100%、平均beauty≥85、Cゲート全通過、予定外接触改善。過去同等回復は平均≥86.277かつp10≥83.786とする。
- A4は一度も動かさない。傾斜アタッチメントの30 mmピボット距離、7.764571 mmオフセット、38 mm穂は変更しない。
- `origin/master`のWindows独立起動・8並列方針だけを取り込み、現在のブランチをcheckout/resetしない。期限は設けず、GitHub・canonical model・既存runへ書き込まない。

## Measured deviation

台座高さ 100 mm では、計画自身の到達条件（位置 3 mm・姿勢 5°・関節余裕 5°）を A4 枠の入口姿勢で満たせない（orientation ≈ 13°）。実測でゲートを通るのは高さ 150 mm・前方 30 mm。紙中心 `(200 mm, 0)` と A4 固定は計画どおり。
