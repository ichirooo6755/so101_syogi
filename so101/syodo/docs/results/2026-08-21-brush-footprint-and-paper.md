# 墨の跡の形と、実機を意識した紙（2026-08-21）

目視所見:「斜め45度で筆を入れるけど、その後同じ筆圧で描いてるからただ単に線が
ウニョウニョしてるようにしか見えない。筆で書いた位置とかは両脇が三角になってるやん。
あれを再現したい。」

**指標ばかり見て実際の字を一度も見ていなかった。** 描き出したら一目瞭然だった。

## 1. 原因: 墨は「楕円を進行方向に並べる」だけだった

```python
radius_squared = (along/major)**2 + (across/minor)**2   # 完全な楕円
angle = 進行方向                                          # 筆の向きではない
```

楕円をいくら並べても**端は必ず丸くなり、起筆の三角形は原理的に作れない**。
実際の筆は円錐で、寝かせて押すと涙滴型の非対称な跡を残す。

しかも `roll`（穂の傾き）も `technique` も既に `deposit` へ渡っており、
**使われずに捨てられていた**。「幅」というスカラーだけを追い、跡の**形**に
一度も触れていなかった。

## 2. 修正: 穂の姿勢で決まる涙滴型

穂の軸を紙面に投影した向きを跡の長軸にし、傾きが大きいほど長軸を伸ばして
穂先側を尖らせる（`taper`）。実測では軸は紙面から 32-48° 傾き、送筆中は
進行方向の逆（穂が後ろに寝ている）を向いている。

```
stretch = 1 + 1.15 * lean      # 傾きが大きいほど長軸が伸びる
taper   = 0.72 * lean          # 穂先側を絞る
半幅    = minor * (1 - taper * clip(along/major, 0, 1))
```

3 字（一十三）IK 天井:

| 指標 | 修正前 | 修正後 |
|---|---:|---:|
| glyph_shape | 62.9 | **77.1** |
| line_width | 88.96 | **94.8** |
| brushwork | 83.49 | **86.4** |

83 字（層化標本）:

| 指標 | 修正前 | 修正後 |
|---|---:|---:|
| beauty | 85.57 | **86.50** |
| line_width | 88.05 | **90.01** |
| brushwork | 82.68 | **86.06** |
| **払い taper** | 約 21 | **27.62** |
| 完筆 / 滴下 / 衝突 | 100% / 0 / 0 | 99%※ / 0 / 0 |

※ 未完筆 1 字（更）は検証スクリプトに入れた 15000 ステップ上限に当たっただけで、
環境自体にステップ上限は無い（鬱は 9027 ステップで完筆）。

## 3. 起筆の三角形 — このハードでは作れない

起筆で穂を 45° に構える姿勢指令を実装したが、IK の姿勢重み（0.003）が小さく
指令が届かない（狙い 40° に対し実際 21°、誤差 23.5°）。重みを上げると:

| 姿勢重み | 結果 |
|---|---|
| 0.003 | 完筆 100%（1028 ステップ） |
| 0.02 | progress 0.55 で滞留 |
| 0.05 | progress 0.17 で滞留 |

関節ごとに穂の傾きへの寄与を数値微分で調べると:

| 関節 | 傾き変化 /0.1rad | 穂先移動 /0.1rad |
|---|---:|---:|
| shoulder_lift | −5.73° | 27.23mm |
| elbow_flex | −5.73° | 26.74mm |
| wrist_flex | −5.73° | 17.19mm |
| **wrist_roll** | **0.00°** | **0.02mm** |

**傾きを変える 3 関節はどれも穂先を 17mm 以上動かす。** 位置を保ったまま傾きだけ
変える冗長性が無い。`wrist_roll` は筆を軸周りに回すだけで傾きに寄与しない。

SO-101 には書道に必要な「手首を返して穂を寝かせる」自由度が構造的に足りない。
**起筆の三角形を腕の姿勢で作るのは、このハードウェアでは不可能。**
`entry_lean` / `finish_lean` は実装だけ残して既定 0（無効）とした。

実機で三角を出すなら、筆ホルダに傾き 1 自由度を足すか、
筆自体を斜めに固定して roll で向きを変える機構が要る。

## 4. 紙: 実機に合わせた（文鎮で上部だけ押さえる）

従来は厚さ 5mm の固定ブロックだった。実機は薄い半紙が上部の文鎮だけで
押さえられ、筆に引かれて浮く。

- 下敷き（毛氈）を追加。紙はこの上に置く
- 半紙を**厚さ 1mm の可動ボディ**に。上端をヒンジで留め、下側は自由
  （`stiffness=6.0` で平らに戻り、`damping=0.35` で暴れを抑える）
- 上部に**文鎮**の geom を配置

実測: 筆に引かれて紙が動き、下端が最大 **0.57mm** 浮く。
字は破綻せず、完筆・滴下・衝突とも変化なし。

## 5. 複数文字（`trajectory/layout.py`）

1 枚 1 字で大きさも固定（A4 で 11-12cm）だったのを、桝目に配置できるようにした。
**字数で大きさが自動的に変わる。**

| 字数 | 一字の枠 |
|---|---|
| 1 | 88×158mm |
| 2 | 88×79mm |
| 4 | 88×39mm |
| 9（3×3） | 29×53mm |

日本語なので既定は縦書き（上から下、右列から左列）。`--horizontal` で横書き。

```bash
python scripts/render_sheet.py --text 春夏秋冬 --rows 2 --columns 2
```

## 6. 残課題

- `solref=0.05` は指標から当てた値で、紙の物性から導いたものではない。
  柔らかさの実体は紙ではなく**穂先**にあるべきで、穂側のコンプライアンスとして
  持たせ直すのが筋（`2026-08-21-paper-contact-stiffness.md` 参照）。
- 起筆の三角形はハード側の自由度不足。機構の追加が要る。
- 合成した紙面（複数字）はお手本マスクを持てないため、glyph 系の採点ができない。
