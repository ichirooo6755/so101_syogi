# 接地筆圧フィードバック（2026-08-19）

[現状課題整理](2026-08-18-current-challenges.md) の主要症状 ——
線幅（一が細い／砕がつまる）、払い・止めの不足、線の癒着 —— の**共通の原因**を特定し、
シミュレータ側で修正した。報酬重みや hard-mining ではなく、接地時の制御の誤りだった。

## 1. 診断: 何が起きていたか

IK エキスパート（`model=None`, action=0 = PPO の天井）で払いの `finish` を分解した。

| 成分 | 重み | 実測 | 内訳 |
|---|---:|---:|---|
| terminal_width | 0.30 | **0.14** | 末端幅 0.0108 に対し目標 0.0058（= 胴体幅のまま） |
| terminal_pressure | 0.24 | **0.40** | 末端圧 0.42 に対し目標 0.17 |
| terminal_speed | 0.18 | **0.03** | 末端速度 0.020 に対し目標 0.150 |
| outgoing | 0.28 | 1.00 | 方向だけは完璧 |

方向は合っているのに、**幅・圧・速度のすべてで「抜けていない」**。
さらにウェイポイント滞留を測ると:

- **全制御ステップの 72–75% が到達待ちの滞留**
- 払いの最終ウェイポイントでは **Z 誤差 1.25mm・圧 0.52 のまま 45 ステップ静止**し、
  そこに墨を落とし続ける（= 末端の団子、隣画との癒着）
- 滞留は払いだけでなく **接地中の全ウェイポイントで発生**（入筆で 23–25 ステップ）

原因は、**位置サーボ単独では接触抗力とつり合った深さで穂先が止まる**こと。
目標より 0.3–0.5mm 沈み込んだまま書くため、

1. 線が太る（line_width 低下）
2. 空中にある払いの最終ウェイポイント（紙面 +0.8mm）に到達できず、抜きが起きない
3. 到達できないので滞留し、墨が溜まって癒着する

到達判定の Z 許容 1.2mm がこの沈み込みを本体部分では隠していたため、
今まで払いの末端でだけ症状として現れていた。

## 2. 修正

`EnvConfig.contact_pressure_gain` / `contact_pressure_limit` を追加し、
接地中は位置だけでなく**筆圧誤差を高さに戻す**（`expert_action`）。

```python
pressure_error = self._pressure - target_pressure   # 正 = 押しすぎ
error[2] += clip(gain * pressure_error, -limit, +limit)
```

書道的には「絶対高さではなく穂先の感触で書く」ことに相当する。
採用値: `gain=0.0050` / `limit=0.0015`。

同時に `max_pen_down_dwell`（滞留上限）も実装したが、**既定は 0（無効）**。
A/B で単独では無益、併用では glyph を下げたため（下表）。
