# 画像の文字を認識して同じ配置で書く（2026-08-21）

要望:「画像に書いてある文字を認識して、その画像の文字の大きさとか位置を
そっくりそのまま書道で書いてくれるようにしたい。」

## 1. 認識: 外部 OCR に頼らない

pytesseract / manga_ocr / easyocr / cv2 はいずれも未導入。代わりに、
**お手本用に既にあるフォント字形マスク**（`_raw_glyph_mask`）をテンプレートとして
照合する。依存が増えず、認識に使った字形をそのまま書字目標に流用できる。

手順は 3 段:
1. 大津の方法で二値化し、連結成分から文字の塊を切り出す（偏と旁のように 1 字が
   複数成分に割れるので、近い成分は束ねる）
2. 各塊をフォント字形と照合して字を決める
3. 画像内の位置と大きさを紙面座標へ写す

## 2. 照合指標の設計

入力がゴシック体、手本が楷書のように**書体が違う**ので、画素の重なりだけでは
足りない。字の骨格が同じかを見る指標を重ねた。

| 指標 | 重み | 狙い |
|---|---:|---|
| IoU | 0.24 | 墨の重なり |
| ブロック平均の一致 | 0.24 | 墨の分布 |
| 布白の数 | 0.18 | 囲まれた空白の位相（田=4、目=3、山=0） |
| 行・列方向の投影 | 0.18 | 墨の量の分布 |
| 重心 | 0.16 | 山と出のような「下に一画足しただけ」の差 |

正規化では**縦横比を保つ**。正方形へ引き伸ばすと縦横比の情報が失われ、
山と出、田と回のように輪郭が似た字を取り違える。

3 字（山・川・田をゴシック体で描いた画像）での結果:

| 正解 | 認識 | 一致度 | 次点 |
|---|---|---:|---|
| 山 | **出** ✗ | 0.787 | 山 0.766（差 0.021） |
| 川 | 川 ✓ | 0.807 | 山 0.681 |
| 田 | 田 ✓ | 0.693 | 回 0.615 |

切り出しは 3 字とも完璧。山と出は指標を重ねて差 0.021 まで詰めたが逆転しない。
**山と出は「山の下に一画足す」関係で、書体差の範囲に収まってしまう。**
候補を絞れば（`--candidates`）実用になるが、常用漢字 2136 字からの無指定認識は
この方式では厳しい。

## 3. 配置: 画像どおりの位置と大きさ

`compose_sheet`（桝目に等間隔）と違い、`layout_from_image` は**画像の相対配置を
そのまま**紙面へ写す。

当初は画像全体を書き枠に収めていたが、余白ぶん字が小さくなり 1 字 19mm まで
縮んで墨で潰れた。**文字が占める範囲**を基準に拡大するよう変更し 24-30mm に。

## 4. 小さい字の線幅

線幅は約 11mm。田のように内部に線が入る字は **60mm を切ると布白が潰れる**。
実際の書でも小さい字は細い筆に持ち替える。

`small_glyph_reference`（既定 60mm）と `small_glyph_floor`（0.30）を追加し、
字幅がこれを下回ると筆圧を落とす。複数字では字ごとに大きさが違うので、
`pressure_scale` を**画ごとの配列**に拡張した。

ただし墨モデルの `width = min + (max−min)·√pressure·opening` は平方根なので、
筆圧を半分にしても線幅は 7 割にしかならない。**13mm の筆で 19mm の字は
原理的に書けない**。実機なら小筆に持ち替える場面。

## 5. 制約

- 横長の画像を A4 縦の書き枠に写すと、幅で頭打ちになって字が小さくなる。
  用紙の向きを画像に合わせるか、紙サイズを選べるようにするのが筋。
- 認識は候補を絞る前提。全 2136 字からの認識には別の手法が要る。
- 合成した紙面はお手本マスクを持てないため glyph 系の採点ができない。
