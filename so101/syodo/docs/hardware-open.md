## 解決済み（経緯）

### 1. 筆を立てるのは ID6 ではなく ID4（2026-09-01 実測で確定）

**これまでの「ID6 で筆を立てる」は、この個体では誤り。** サーボで両端まで送って実測した:

| 項目 | 実測（手で当たるまで動かして確認） |
| --- | --- |
| 立つ側の端 | **731 tick** |
| 寝る側の端 | **2541 tick** |
| 実可動 | 1810 tick = **159.1°** |
| 旧 LeRobot 較正レンジ | 1636–3098。**立つ側 905 tick（80°）が範囲外だった** |
| 現レンジ | 731–2541 に修正済み |

分かったこと:

- 旧レンジでは、筆が立っていても実位置が下限より下なので読みは **0.0% に張り付く**。
  `stroke` はその 0.0%（＝1636 tick）を書き戻すので、立っていた筆が寝る方へ動いていた
- したがって筆が寝ていた原因は ID6 の指令そのもの。ただし立てる主役は **手首曲げ ID4**
- 筆が寝ていても **ID4 を下に曲げれば立つ**（実機で確認）
- ID6 はトルクを切っても落ちない（自己保持）。自重で寝るのではない

**丸められるのは ID6 だけ。** 正規化モードは ID6 のみ `RANGE_0_100`、腕 5 軸は `DEGREES` で
tick から直接角度に換算される（肘の実測 2207 tick と読みの差 194.0° が一致）。
較正レンジは腕では位置リミットにしか効かない。
`peek` は生 tick も出すようにした。端に張り付いたらそれで分かる。

肘（ID3）も実測した: 伸ばしきり **1864** / 曲げきり **4071** = 2207 tick = 194.0°。
旧リミット 1852–4055 は曲げ側が 16 tick（1.4°）足りなかっただけで、読みは正しかった。
リミットは実測へ合わせた。

以前この欄に書いた「FK で `upright` と 0.3° 差」は撤回。ID6 の 0–100% が MJCF の筆傾き全域を
張るという未検証の仮定に乗っていた。

較正修正前の姿勢は ID6 の真値が残っていなかったので、11 姿勢すべて取り直した。

**ID6 の % → MJCF 角は較正値になった。** ゲインは tick 幅で決まる物理量（−1.591°/%、
`GRIPPER_DEG_PER_PCT`）なので固定し、ゼロ点だけ直立教示から当てる（`fit_gripper_map`）。
結果は `desk.gripper_map_rad`。以前は 0–100% を MJCF 可動域 110° に引き伸ばし、
他 5 軸にはあるゼロ点補正が ID6 だけ無かった。それが四隅を「58〜88° 傾き」と誤判定させていた。

寝たまま取った教示は、必要な ID6 角が % の一次式から外れるので検出できる。
ゼロ点は中央値で取るため、1 つ混ざってもゼロ点は引きずられない。

### 2. 肩・肘のゼロ点（2026-09-01 解決）

**目視の L 字（`sim_home`）は肘で 25° ずれていた。** 目視ではここまで詰められない。
四隅と中央は同じ机に接地しているので、**穂先 z が揃う**という制約のほうがはるかに強い。
`refine_arm_offsets` がそこから肩・肘を詰める。紙の寸法も ID6 の % 較正も使わない。

| | sim_home 目視 | 四隅から補正 |
| --- | --- | --- |
| 肩 | −88.20° | **−78.70°** |
| 肘 | +77.82° | **+52.32°** |
| 四隅 z 幅 | 28.5 mm | **1.2 mm** |
| 下手左→下手右 | 129 mm | **153.9 mm** |

検証は較正に使っていない定規の実測 155 mm。差 1.1 mm。

両方とも `desk.json` に残る（`joint_offsets_deg` が採用値、`joint_offsets_sim_home_deg` が目視値）。

### 3. 未解決: 実機12/8/4 cm構成の学習・物性同定

旧`hardware-12cm`は「穂が12 cm」という誤った前提なので起動しない。Cゲートは3.8 cm穂の`kaisho-yohitsu-sansetsu`。実機の穂4 cmは近いが、把持位置から穂元までの8 cm剛体軸と実測物性を含む構成は未採択である。実機の線と荷重で同定するまでcanonicalにしない。

## 試し書きの経過

| 回 | 結果 | 原因 |
| --- | --- | --- |
| 初期 | 空中、筆が寝た | 接続で前回の目標（寝た hover）へトルク。肘を開いた hover への補間で筆が寝る |
| 修正後 | 毛先は机。筆は約 45° | 取り直し前の四隅。折りが違うので筆が寝ていた |
| 手首曲げ −9° で再教示して再送 | コマンドは成功 | |
| hover 経由で再送 | 筆が寝た | 肩を hover_center（−12°）まで +41° 上げていた |
| hover を廃して再送 | 筆はまだ寝たまま | 四隅の ID4 が足りない。ID6 は端で調整余地なし |
| ID6 較正を直して四隅を取り直して再送 | **成功。筆は立ったまま紙を左から右へ** | |

接続時は今の姿勢を目標にしてからトルク ON。切断時はトルク OFF。`stroke` は hover に上げない。下手左へ行ってから土台だけ左右。ID5・ID6 は開始時の値で固定。
`--mark-s N` で両端に N 秒静止する（印をつけて実測する用）。

## 机と筆（確定）

- 把持位置→毛先12 cm＝筆軸8 cm＋穂4 cm（採択モデルの穂は3.8 cm）
- 半紙 縦置き 333×242 mm。土台と紙は同じ高さ
- **書字領域は紙の15 mm余白内。** 現測は267×154 mm。1文字は約124 mm角、2文字は約118 mm角を縦2段、3〜4文字は約62 mm角の2×2配置。字形比を保ち各辺2 mmの筆跡余白を残す。実機IKが通る最大候補を100〜80%の2%刻みで検証し、`trace.layout.svg`に枡と軌道を保存する。`hw-write`はKanjiVGにある1〜4文字なら可。`record-word`だけ`文字・学習・菅原`。
  `fit_paper` は紙の実寸と突き合わせない（ゼロ点の検査は四隅の z 幅 10 mm 以内で行う）
- 学習用シミュ既定は A4 横長＋150 mm 台のまま。実機パスだけ差し替え
- 開ループのtraceでも Motoya の `fit_trajectory_to_exemplar_shape` は掛かる
