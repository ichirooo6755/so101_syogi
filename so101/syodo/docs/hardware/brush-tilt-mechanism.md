# 筆傾斜機構 設計書（Fusion 360 用）

SO-101 のグリッパー用サーボを筆の傾斜軸に転用し、楷書の起筆（三角形の入り）を
実現するための機構設計。

## シミュ統合の確認（2026-09-08、#13）

現在の MJCF は `brush_tilt_link` 内の Y 軸 `gripper` に筆・穂を載せ、姿勢付き IK は
第6軸を使う。採用した最終 CAD は下記の **30 mm**。issue 冒頭の 36.722 mm は旧値。
`tests/test_brush_tilt.py` が親子構造、軸、オフセット、45°回転時の穂先移動と、
−15° / +15° / +30° の軸方向変更を穂先位置 0.5 mm・姿勢 2°以内で補償することを検証する。
この最後の検証は FK/IK の幾何スモークであり、紙との接触や学習品質の評価ではない。

`entry_lean` は現在の設定では有効。起筆角を追えば品質が向上するという保証はなく、
接地圧・線幅・布白・完筆の strict gate は別途必要。38 mm の学習穂と実機の筆軸80 mm＋穂40 mmも
別条件として扱う。[issue 対応記録](../results/2026-09-08-open-issues.md) に検証をまとめた。

## 1. なぜ必要か

当初は、穂を斜めに寝かせた接触面の伸びを起筆へ使うことを狙った。
その後の圧力スクリーンでは固定斜筆＋Z筆圧も検討しているため、画中の角度変化を
三角形の必須条件とはしない。以下の表は機構追加前の姿勢自由度の診断記録。

現状の SO-101 では作れないことを実測で確認済み（`docs/results/2026-08-21-brush-footprint-and-paper.md`）:

| 関節 | 傾きへの寄与 /0.1rad | 穂先移動 /0.1rad |
|---|---:|---:|
| shoulder_lift | −5.73° | 27.23mm |
| elbow_flex | −5.73° | 26.74mm |
| wrist_flex | −5.73° | 17.19mm |
| **wrist_roll** | **0.00°** | 0.02mm |

傾きを変える 3 関節はどれも穂先を 17mm 以上動かす。**位置を保ったまま傾きだけ変える
冗長性が無い。** IK の姿勢重みを上げると位置が破綻し、完筆率が 100% → 0% になる。

## 2. 着眼点: グリッパーは完全に空いている

機構追加前の MJCF では、筆は `wrist_roll_link` に**剛体で直付け**されており、
グリッパーの顎（`moving_jaw_link`）は筆に一切関与していない。
書字中グリッパーは何もしていないので、**サーボを傾斜軸に転用できる。**

## 3. 軸の向き — 最終 CAD を正とする

初期検討では純正顎モデルの軸を z とみなし、`wrist_roll=90°` で傾斜軸へ向ける案を
試した。最終アタッチメントの STEP では、サーボ出力軸は
`Wrist_Roll_Follower` 座標系の **Y 軸**として組み込まれている。

重要なのは、**筆がサーボ軸と同じ向きに付くのではない**こと。筆軸はサーボ軸に
直角で、アタッチメントによって中心線も回転軸から離れている。

| 項目 | 最終値 |
|---|---:|
| サーボ軸 | Y |
| 軸位置（Follower 座標） | x=20.077 / z=24.350 mm |
| 筆軸 | −Z（サーボ軸と直角） |
| 筆中心線オフセット | +X 7.764571 mm |
| 穂先（ピボット基準） | (7.764571, 0, −28.977775) mm |
| ピボット→穂先 | 30.000 mm |

したがって最終モデルに追加の `wrist_roll=90°` 固定は入れない。STEP 内の Y 軸を
そのまま `gripper` ヒンジとして使う。

## 4. ピボット位置 — 最重要の設計パラメータ

傾けると穂先が動く。移動量は概ね `2·L·sin(θ/2)`（L = ピボットから穂先までの距離）。

| L | θ=20° | θ=30° | θ=45° |
|---:|---:|---:|---:|
| 80mm | 27.8mm | 41.4mm | 61.2mm |
| 40mm | 13.9mm | 20.7mm | 30.6mm |
| **30mm** | **10.4mm** | **15.5mm** | **23.0mm** |
| **20mm** | **7.0mm** | **10.4mm** | **15.3mm** |
| 10mm | 3.5mm | 5.2mm | 7.7mm |

初期の純正顎位置では穂先から約 95mm あり、45° 回すと **73mm** 動いた。最終 CAD は
筆を切ってピボット近傍で掴み、距離を正確に 30mm へ縮めた。

**穂先の移動をゼロにはできない**（穂先は紙に触れる点なので、そこに軸受けは置けない）。
しかし穂先位置は IK が制御しているので、**変位を IK が吸収できる大きさに収めれば
実用上問題ない。**

### ▶ 確定値: **L = 30mm**

45° で 15〜23mm。wrist_flex 単独でも 0.1rad あたり 17mm 動かせるので、
IK が十分吸収できる。L を 10mm 以下にすると機構が成立しない
（サーボ本体と筆軸が干渉する）。

## 5. トルク要件 — 桁違いに余裕がある

| 筆＋ホルダ質量 | 重心までの腕 | 必要トルク |
|---:|---:|---:|
| 15g | 30mm | 4.4 mNm (0.05 kgf·cm) |
| 15g | 40mm | 5.9 mNm (0.06 kgf·cm) |
| 15g | 60mm | 8.8 mNm (0.09 kgf·cm) |

SO-101 のサーボ **STS3215 は約 30 kgf·cm（7.4V）**。必要量の 300 倍以上。
**トルクは全く問題にならない。** 剛性と精度だけを考えればよい。

## 6. 可動域

グリッパーの可動域は **−10° 〜 +100°（110°）**。
書道に必要なのは送筆 12° / 起筆 40〜45° なので、**十分すぎる**。

## 7. Fusion 360 での設計手順

### 7.1 準備するもの

| 項目 | 内容 |
|---|---|
| 参照 STEP | SO-101 の wrist_roll_link とグリッパーアセンブリ（TheRobotStudio 公開データ） |
| サーボ | STS3215（既存のグリッパー用をそのまま使う） |
| 筆 | 穂の長さ 22mm、軸径 7mm（φ7）を想定。実物を計測して更新すること |
| 材料 | PLA または PETG、積層 0.2mm、インフィル 40% 以上 |

### 7.2 パラメータ（Fusion のユーザーパラメータに登録）

これらを変数にしておけば、実物採寸後の修正が一箇所で済む。

| パラメータ名 | 既定値 | 意味 |
|---|---:|---|
| `pivot_to_tip` | 25 mm | ピボット中心から穂先まで。**4 節の設計目標 20〜30mm** |
| `brush_dia` | 7 mm | 筆軸の直径 |
| `brush_grip_len` | 18 mm | 筆軸を掴む長さ |
| `horn_dia` | 20 mm | サーボホーンの外径 |
| `horn_screw_pcd` | 14 mm | ホーン取付ネジのピッチ円直径 |
| `wall` | 2.4 mm | 外壁厚（ノズル 0.4mm × 6） |
| `tilt_min` | −10 deg | 傾斜の下限（グリッパー可動域） |
| `tilt_max` | 100 deg | 傾斜の上限 |

### 7.3 部品構成（3 点）

```
① チルトブラケット   … サーボホーンに固定、筆ホルダを支持
② 筆クランプ         … 筆軸を挟んで保持（割締め）
③ カウンタ支持       … ピボットの反対側を受ける軸受け（片持ちを避ける）
```

### 7.4 モデリング手順

**① チルトブラケット**

1. サーボホーン面をスケッチ平面にする（XY 平面）
2. `horn_screw_pcd` の円周上に 4 つの M2 皿ネジ穴（φ2.2 貫通、皿深さ 1.2mm）
3. 中心に φ`horn_dia`+0.4 の逃げ座ぐり（深さ 3mm）— ホーンの厚みを逃がす
4. そこから `pivot_to_tip` 方向へアームを押し出し（幅 12mm × 厚 `wall`×2）
5. アーム先端に筆クランプの取付面（M3 × 2 箇所、ピッチ 16mm）

**要点:** ホーン中心と筆軸の距離が `pivot_to_tip` になるよう配置する。
これが 4 節で決めた最重要パラメータ。

**② 筆クランプ**

1. φ`brush_dia`+0.3 の穴を `brush_grip_len` の長さで押し出し
2. 片側にスリット（幅 1.6mm）を入れて割締めにする
3. スリットを跨ぐ M3 タップ穴（またはナット座）
4. 筆の抜け止めに、穴の奥に φ`brush_dia`−1 の段付きを設ける

**要点:** 筆は消耗品なので**工具なしで交換できる**こと。蝶ネジ推奨。

**③ カウンタ支持**

1. サーボと反対側の固定顎の位置に、φ4 の軸受け穴を持つブラケット
2. チルトブラケットから φ3.9 のピンを突き出し、ここへ嵌める
3. 軸線がサーボ出力軸と**同一直線**になること（ズレると渋くなる）

**要点:** 片持ちにすると筆先が振れる。両持ちにして剛性を確保する。

### 7.5 検証（Fusion 上で）

1. **干渉チェック** — グリッパー角を −10° / 0° / 45° / 100° に振って、
   筆軸・ブラケット・手首本体が当たらないこと
2. **動作範囲** — ジョイントを定義して実際に回し、穂先の軌跡を確認
3. **穂先移動量** — 45° 回したときの穂先の移動が **23mm 以内**であること
   （4 節の計算と一致するか）
4. **質量特性** — 解析 → 物性で筆込み質量とピボットまわりの重心を確認。
   **25g・腕 40mm 以内**に収まれば 5 節のトルク余裕は保たれる

### 7.6 印刷とアセンブリ

| 項目 | 推奨 |
|---|---|
| 積層方向 | ピボット軸に対して**垂直**に寝かせる（層間剥離を軸荷重に向けない） |
| インフィル | 40%（ジャイロイド） |
| サポート | クランプのスリットのみ |
| 後処理 | 軸受け穴を φ4.0 リーマ通し |

## 8. ソフト側の対応

機構だけでは動かない。以下の変更が要る。

### 8.1 MJCF（`assets/so101_calligraphy.xml`）— 最終 CAD 寸法を実装

`brush_tilt_link` のピボットを Follower 基準 `(20.077, 0, 24.350)mm` に置き、
筆中心線を +X へ 7.764571mm オフセットした。筆軸は −Z、穂の根元は
`(7.764571, 0, 9.022225)mm`、穂先は
`(7.764571, 0, −28.977775)mm`。旧実装の「29mm の折れを消して軸上へ伸ばす」近似は
削除した。

サーボの電気角 45°を筆の直立ホームに較正する。印刷部品の `yoke_index=0°` は変えず、
可動域 −10°..100°を直立基準の有効傾斜 −55°..+55°として使う。

短い筆で elbow-up 可動域を確保する実機配置は、台座スペーサー 35mm、紙中心
x=305mm、紙余白 75mm。紙・墨池・硯縁は穂先だけと接触させ、軽量表示用の粗い腕
プリミティブで実在しない 0.1mm 接触を作らない。

### 8.2 IK（`envs/calligraphy_env.py`）— 実装済み

gripper を全区間で 6 軸目として DLS に入れる。搬送・硯では直立を保ち、書字中は
`entry_lean=1.0`（起筆 約45°）を含む目標筆軸へ動かす。リセットは床を横切らない
elbow-up 枝から開始する。

### 8.3 学習

物理が変わるので**全段階の再学習**が要る。既存の較正値
（`tuft_opening` 1.34 / `contact_pressure_gain` 0.015 / `exemplar_density_fit` 0.5）
はいずれも現機構での値なので、再点検すること。

## 9. リスクと代替案

| リスク | 対策 |
|---|---|
| 印刷部品の剛性不足で筆先が振れる | 両持ち支持（③）を必ず入れる。PETG 推奨 |
| ピボットが遠すぎて IK が破綻 | `pivot_to_tip` を 30mm 以下に抑える |
| グリッパーを失い物を掴めない | 書字専用機なので許容。掴む必要があるなら別案へ |
| サーボの片側可動域へ張り付く | 電気角45°を直立ホームにし、有効域を−55°..+55°へ対称化 |

**代替案（機構を足したくない場合）**: 筆を最初から 40° 傾けて固定し、
`wrist_roll` で向きだけ変える。部品は筆ホルダ 1 点で済むが、
**送筆中も常に傾いたまま**になるため、三折法の「起筆だけ寝かせる」は再現できない。

## 10. 期待できる効果

現状（IK 天井、44 字）の払い taper は 11.10。墨の跡を筆の姿勢で決まる形にした
改良で 28.43 まで上がったが、**姿勢そのものを制御できないため頭打ち**。

この機構が入れば起筆で 40〜45° に構えられるようになり、
`docs/results/2026-08-21-brush-footprint-and-paper.md` で不採用にした
`entry_lean` / `finish_lean` が初めて機能する。

**目視所見「両脇が三角になってる、あれを再現したい」への直接的な解。**
